# Changelog

## Unreleased (0.2.0)

- `graft crossref` re-asks on form errors (M14b): UNANSWERED and DANGLING entries (e.g. a `location` written as prose) are fed back to the model with the exact validation messages, within `--retries` (default 2), before a proposal with such entries is written (exit 4; `--strict` now makes that exit 1, nothing written). The prompt states the location form (`<file>: <Identifier>`) and lists each target's available identifiers (the skeleton's symbols in render mode; top-level names of an existing Go file under `--root` otherwise). `graft bench run --model "ARGV"` runs with another model command and records it as the model.
- **Cross-reference step (M14), and a behaviour change.** A spec change can no longer silently drop a rule that is stated in one section but must be enforced in another section's code. New `graft crossref` (propose-never-apply, like `graft draft --skeleton`): one model call per spec change decides, for each statement that is new or changed, whether it is `local` or `constrains` other records, with a receipt (the statement, the target record, a reason, the code location, a quote from the target) that is validated for form. `graft run --accept --crossref crossref.json` copies each accepted statement into the target record, which is revised and regenerated; the link to the source lives in `.graft/accepted.json` and the copy follows its source when it is edited or removed.
- **Upgrading from 0.1.0: `graft run --accept` now exits 2 after a spec change** that adds or edits a statement nobody cross-referenced, before it writes anything. Run `graft crossref ...` and pass `--crossref crossref.json`, or pass `--no-crossref` to accept unchecked (it prints how many statements were not checked). The first accept, and a re-run of an unchanged spec, need neither. A new `cross-references: ...` summary line follows the `regions applied` line, and every `local` verdict is printed.
- **Known limit:** a well-formed but wrong `local` verdict still drops the rule silently; validation checks the form of an answer, not its truth. The advisory warnings `graft crossref` prints (a `local` statement that names something another record uses) never change an exit code.
- `graft bench`: the graft and graft-render evolve arms run the cross-reference step with the arm's model before accepting the change; the change-cost lines show its call (`crossref_calls`).
- **One gen_hash (M13).** sedum 0.14 reads a record's shape, so its markers carry the same `gen_hash` graft computes. graft drops `Pin.SedumGen`, the second, shape-less hash it kept for sedum.
- **Requires sedum >= 0.14.0.** graft refuses an older sedum with a clear error (`graft needs sedum >= 0.14.0, found 0.13.0`) before it renders anything, in `graft run --render`, `graft bench` and `graft draft --skeleton`.
- **Upgrading from 0.1.0:** 0.1.0 render trees re-render once on upgrade, with no model calls. sedum's files get markers that carry the full gen_hash; every synth body is byte-identical, and only a region that then fails its gates is regenerated.
- Trees made before M11a (never released) are no longer upgraded cheaply: their markers carry a shape-less gen on every region, so the regions regenerate.

## 0.1.0

The first tagged release. graft turns a markdown spec into code, one region per section. Each region lands only when its gates pass, and is regenerated only when its record changes or it stops passing.

- **Records:** each spec section becomes a versioned provenance imprint. Records are drafted (`graft draft`) and accepted (`graft run --accept`).
- **Convergence:** each section's region is generated by your model command and applied only when the configured gates pass and the tier's policy is satisfied (`guarantee: checked`). Every verdict is logged, hash-chained, and pinned to the record, the code and the spec.
- **Re-runs and hand edits:** unchanged sections are re-verified with no model call, and hand edits inside a region are refused.
- **Sign-off:** `graft signoff` records human sign-off evidence, pinned like every other piece of evidence, so it goes stale when the code, record, spec or skeleton moves. `--by` is recorded as given and **not authenticated**.
- **Best-of-N:** `--samples N` draws N candidates per attempt and keeps a passing one.
- **`--render`:** sedum (≥ 0.13.0) renders the skeleton deterministically and the model writes only the helper bodies. The skeleton lives in the records (M11a): a shape edit re-verifies every region with no model call and regenerates only the regions that fail.
- **Languages:** Go by default; a `"language"` profile adds Python, TypeScript or any other language. `--render` works in any language with a sedum generator.
- **Existing repos:** `"files"` places a section in a chosen file, which then lives in the record's `affected_scope`.
- **Bench:** `graft bench` compares graft with one-shot generation against a held-out oracle, with intervals, recorded visible/held-out overlap, and cost.
- **Examples:** freeq-lite (Go, Python, TypeScript) and ledger-lite (cross-section rules).
- **Docs:** [docs/tutorial.md](docs/tutorial.md) and [docs/real-repo-trial.md](docs/real-repo-trial.md).

**Known limits:**
- Under a tier that requires `human_signoff`, a **new** body can't land yet. A sign-off covers a region already in the tree; signing a checked candidate before it's applied is planned.
- `graft draft --skeleton` (M11b) isn't built yet.
- sedum doesn't read shape from the records yet, so graft keeps a second, shape-less hash just for sedum.
- The prompt includes every source file under the root.
- On graft's own yardsticks, graft doesn't beat one-shot generation on correctness. What it adds is the guarantees above.
